# 2026-05-09 工作记录

## 修复靶场环境启动/停止问题

### 问题描述
靶场管理页面中，点击"启用"按钮后页面显示成功信息，但 Docker 容器和页面状态均未改变。

### 根因分析
1. **条件判断 Bug**: `compat_env_start` 和 `compat_env_stop` 中使用 `if not container and not target:`，
   导致 target 已找到的情况下不会尝试用 target_id 直接查找 Docker 容器，进而可能拿到错误的容器对象或容器为 None
2. **无操作验证**: `container.start()` 调用后不检查容器实际状态，即使 SDK 返回成功但 Docker 未实际启动也无感知
3. **无降级方案**: 完全依赖 Docker Python SDK，Windows 下 Docker SDK 连接可能存在兼容性问题
4. **零日志**: 没有任何调试日志，无法定位问题

### 修复内容 (routes/compat.py)
1. 将 `if not container and not target:` 改为 `if not container` — 不管 target 是否找到，只要容器没找到就继续尝试
2. 增加 `reload()` 检查容器当前状态，已运行时跳过启动
3. 增加 Docker CLI (`subprocess` 调用 `docker start/stop`) 作为 SDK 失败时的降级方案
4. 增加全链路日志，每步都记录 identifier、查找结果、容器状态
5. 启动/停止后增加 `time.sleep(1) + container.reload()` 验证并返回 `final_status`
